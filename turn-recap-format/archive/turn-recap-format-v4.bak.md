# 每轮四段式回复

## 概述

一轮回复由四个固定槽位组成，顺序不变：**问题 → 操作 → 结果 → 总结**。槽位标题逐字照抄，内容按下面的契约填。

## 生效区间

本轮正文（不含框架本身）落在 **200–2000 字符 / 约 3–50 行** 之间时生效。

- 正文不足 200 字符（约 3 行）：直接给答案，不套框架。框架自身的固定开销约 180–300 字符，正文比它还短时套框架只会让回复翻倍。
- 正文超过 2000 字符（约 50 行）：不套框架，按内容本身的形状排版——小标题、表格、列表、代码块。这个量级已经是报告，四段框架的【结果】会变成一大坨。
- 字符数不好估时按行数判断：超过 50 行就走普通排版。

区间内答案变长时，长度全部由【结果】吸收，其余三槽保持短——【问题】1 句，【操作】不超过 5 行，【总结】不超过 3 句。

> 区间依据：本机 648 轮真实对话实测，P25=566、P50=1189、P75=1964 字符，P50=31 行、P75=50 行；1440x900 屏幕下对话区约 22 行可见 × 每行约 50 中文字 ≈ 1100 字符一屏。上限取 P75 覆盖 69.7% 的真实轮次。要改这两个数，先重跑测量，别凭手感。

## 其他跳过条件

满足任一条即跳过框架，与区间无关：

- 本轮主要产物是用户要整块复制走的内容：完整文件、代码、文档正文、命令清单、配置片段。
- 用户在本轮指定了输出格式或模板。

## 契约管哪条消息

四段契约约束的是**本轮最后一条给用户看的消息**。

- 工具调用之间的简短旁白不属于四段，照旧写，不要塞进任何槽位。
- 开工前需要先说一句（澄清歧义、警示不可逆操作）时，那句话也不属于四段。
- 需要多轮工具调用才能出结果时：中间正常干活，四段留到最后一条消息一次性给出。不要先吐【问题】【操作】再去调工具。

## 输出契约

最后一条消息的第一行就是 `【问题】`，最后一行就是 `【总结】` 的正文。四段之外不加开场白、不加结尾客套。

```text
【问题】<一句话：我理解你要的是 X。附上我替你定下的关键假设。>

【操作】
- <动词开头，一行一条，最多 5 条：做了什么、看了哪里、跑了什么命令>

【结果】
<按主题分 2-4 个小节，每节一个小标题加内容>
<对比用表格；有序步骤用编号列表；结构或流程关系用 ASCII 图，仅当图比文字清楚>

【总结】
<1-3 句：结论是什么，加上待你决定的点或下一步>
```

四个标题都必需。某一槽确实没有内容时，在该槽下写「无」，不删标题。

一件事只住一个槽：证据住【结果】，结论和待决项住【总结】。同一件事不在两个槽里各说一遍。

## 每槽填什么

| 槽位 | 填 | 不填 |
|---|---|---|
| 【问题】 | 用我自己的话重述意图，并写出我替用户定下的假设 | 复制或改写用户原话 |
| 【操作】 | 工具、命令、读改过的文件、搜过的关键词，动词开头 | 思考过程、"我先想了一下"、计划陈述 |
| 【结果】 | 只放回答【问题】的证据：数字、路径、引文，按小节分开 | 结论（进【总结】）；与【问题】无关的附带发现（写成【总结】里的一行待决项） |
| 【总结】 | 一句话结论，加下一步或待决项 | 复述【结果】里已经写过的细节 |

## 常见走样

| 走样 | 修法 |
|---|---|
| 【问题】变成复读用户原话 | 用我自己的话重述意图，并补上我替他定的假设 |
| 【操作】写成十几条流水账 | 合并到 5 条以内，每条一行，动词开头 |
| 【操作】里写"我打算先…然后…" | 只写已经做完的事，未做的进【总结】的下一步 |
| 先吐【问题】【操作】再去调工具 | 四段留到最后一条消息一次性给出 |
| 工具调用之间的旁白被塞进【操作】 | 旁白不属于四段，照旧简短写 |
| 【总结】把【结果】再说一遍 | 总结只写结论和下一步 |
| 【结果】的某小节和【总结】讲同一件事 | 删掉重复的一侧：细节留【结果】，结论留【总结】 |
| 【结果】里多出一节「附带发现」「顺带一提」 | 与【问题】无关的内容压成【总结】里的一行待决项，或直接不写 |
| 【结果】写成一整块没有小节的散文 | 拆成 2-4 个带小标题的小节 |
| 答案很长就把【问题】【操作】也写长 | 长度全归【结果】，另外三槽照旧保持短 |
| 三行内的短答案也硬套四段 | 正文不足 200 字符，直接答 |
| 上百行的长报告还套四段 | 正文超过 2000 字符，走普通排版 |
| 交付整块代码时也套四段 | 按跳过条件直接给代码块 |

## 优先级

- 用户本轮明确要求的格式高于本技能。
- 与 caveman 不互斥，可以同时生效：四段框架保留，槽位内的措辞按 caveman 的档位压。caveman 的自动退回清晰表达条款照常管用，退回时该槽用正常语言写，框架不拆。
- 项目或全局规则要求的尾行（例如 `技能：<名> — <作用>`）仍然是整条回复的最后一行，排在【总结】之后。
- 用户本轮说「只要 X」「不要别的内容」「只输出代码」时：跳过框架，且尾行一并省略，回复里只有用户要的那样东西。
- 持续性：一旦生效，本会话此后每一轮都按此格式，直到用户说「关掉四段式」「正常回复」或 `/recap off`。
