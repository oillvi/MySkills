# 每轮四段式回复

**先记一条：四段只出现在本轮最后一条给用户看的消息里。开工前不要吐【问题】，工具调用之间不要吐任何槽位标题——那时你还没做完，【操作】只能写计划，而计划不属于任何槽位。开工前要说的话（澄清、警示不可逆操作）用普通句子写，不带槽位标题。**

## 路由：先判本轮属于哪一类

| 本轮的情况 | 怎么回 |
|---|---|
| 正文（框架外的散文）不足 200 字符 / 约 3 行 | 直接答，不套框架 |
| 正文 200–2000 字符 / 约 3–50 行 | **套四段框架**（本技能主体） |
| 正文超过 2000 字符 / 约 50 行 | 不套框架，按内容形状排版：小标题、表格、列表 |
| 主要产物是用户要整块复制走的东西：完整文件、代码、文档正文、命令清单、配置片段 | 只给那样东西，框架和尾行都省略 |
| 用户指定了格式，或说了「只要 X」「不要别的」「太长」「直接给结论」 | 照用户说的办，框架和尾行都省略 |
| 本轮走了 `/canvas`，产出 `.canvas.tsx` | 套框架，但【结果】退化成指针型（见「与 canvas 的分工」） |

字符数只数框架外的散文，**围栏代码块不计入**。字符数不好估时按行数判：超过 50 行就走普通排版。

> 区间依据：本机 648 轮真实对话实测，P25=566、P50=1189、P75=1964 字符，P50=31 行、P75=50 行；1440x900 屏幕下对话区约 22 行可见 × 每行约 50 中文字 ≈ 1100 字符一屏。上限取 P75，覆盖 69.7% 的真实轮次。要改这两个数，先重跑测量，别凭手感。
>
> 临界拿不准时（190–210 字符、48–52 行）：套框架。宁可多套一次，不要在该套的时候漏掉。

## 框架管哪条消息

四段只约束**本轮最后一条给用户看的消息**。

- 工具调用之间最多写一句简短旁白——工具结果本身就是记录，旁白不属于四段，不要塞进任何槽位。
- 四段留到最后一条消息一次性给出。不要先吐【问题】【操作】再去调工具：那样【操作】只能写计划，而计划不属于任何槽位。
- 用户确认后的追加消息只写增量，不重出四段。

最后一条消息的第一行就是 `【问题】`，最后一行就是 `【总结】` 的正文。

```text
【问题】<一句话：我理解你要的是 X。假设 <我替你定了什么>，所以我走 <A> 而不是 <B>。>

【操作】
- <动词开头，一行一条，最多 5 条；每条对应一次真实发生的工具调用或文件读写>

【结果】
<按主题分 2-4 个小节，小节标题加黑：**小节名（状态）** 加内容>
<对比用表格；有序步骤用编号列表；结构或流程关系用 ASCII 图，仅当图比文字清楚>
<每条结论挂一个状态词：已验证 / 待确认 / 超出范围 / 不适用>

【总结】
<结论一行；待决项一条一行，格式 `- **[标签] 短语**：说明`，标签按 [必须定] [建议] [可选] [待你答] 分级>
<待决项再多也不许合并成一段密排长文>
```

四个标题都必需。某槽确实没内容时写「无」，并注明是**没做**还是**做了没结果**。

一件事只住一个槽：证据住【结果】，结论和待决项住【总结】。

槽位标题只属于聊天层。用户要复制走的代码块、文件内容里不许出现【问题】这类标题。

## 每槽的硬要求

| 槽位 | 必须 | 不许 |
|---|---|---|
| 【问题】 | 用自己的话重述意图；假设写成「假设 X，所以走 A 不走 B」，让用户一眼能纠正 | 复制或改写用户原话；只写假设不写它导致的取舍 |
| 【操作】 | 每条对应一次真实发生的工具调用、命令或文件读写 | 编造没跑过的步骤；写「我打算先…」；超过 5 条 |
| 【结果】 | 数字、路径、引文，按小节分开；每条结论挂状态词 | 结论（进【总结】）；与【问题】无关的附带发现（压成【总结】一行待决项）；「应该」「大概」「似乎」 |
| 【总结】 | 结论一行，加分级待决项；待决项一条一行，`- **[标签] 短语**：说明` | 复述【结果】的细节；挤成一段密排长文；「太好了」「搞定」「完美」这类没验证就先满意的词 |

## 常见走样

| 症状 | 成因 | 修法 |
|---|---|---|
| 【问题】和用户原话一模一样 | 把重述做成了复述 | 换成自己的话，补上假设导致的取舍 |
| 【操作】列了没跑过的步骤 | 把计划当成了记录 | 只写真实发生的调用，未做的进【总结】下一步 |
| 开工就先吐【问题】【操作】 | 误以为框架约束每条消息 | 框架只管最后一条消息 |
| 【结果】冒出「附带发现」「顺带一提」 | 无关观察塞进了证据槽 | 压成【总结】一行待决项，或不写 |
| 【结果】某节和【总结】讲同一件事 | 一件事住了两个槽 | 细节留【结果】，结论留【总结】 |
| 正文变长时【问题】【操作】跟着长 | 长度分配没守住 | 长度全归【结果】：【问题】1 句、【操作】≤5 行、【总结】1 行结论加待决项逐条 |
| 【总结】写成一大段密排长文 | 待决项没逐条拆，标签淹没在正文里 | 拆成一条一行，`- **[标签] 短语**：说明`，【结果】小节标题同步加黑 |
| 三行短答案硬套四段 | 没走路由表 | 不足 200 字符直接答 |
| 上百行报告还套四段 | 没走路由表 | 超 2000 字符走普通排版 |
| 交付代码块时套四段 | 产物和解说混在一起 | 只给代码块，框架和尾行都省 |

## 自动退回：本轮弃用框架

出现任一种，本轮不套框架，用正常语言直接说清楚，下一轮恢复：

- 安全警告、不可逆操作确认。
- 用户追问、重复提问，或说「没看懂」「再说一遍」——说明四段这轮没帮上忙。
- 套完框架反而比不套更长。

## 与 canvas 的分工

canvas 把量化分析、指标、分级发现、表格图表**搬出聊天**做成 `.canvas.tsx`（canvas SKILL.md:12-17），本技能相反，是把短内容**在聊天里**结构化。两者同一轮生效时按下面办，不做全量互斥：

- 框架保留，【结果】退化成指针型：只给 canvas 文件的绝对路径 Markdown 链接，加不超过 3 行说明文件里有什么。不把 canvas 内容抄回聊天。
- 200–2000 区间只按聊天正文算，不含 canvas 里的内容。
- 路由表里「超 2000 字符走普通排版」这一条，在 canvas 生效时改成「搬进 canvas」。

## 其他优先级

- 与 caveman **不互斥**，可同时生效：框架保留，槽内措辞按 caveman 档位压。caveman 的自动退回条款照常管用，退回时该槽用正常语言写，框架不拆。
- 项目或全局规则要求的尾行（如 `技能：<名> — <作用>`）仍是整条回复最后一行，排在【总结】之后。用户说「只要 X」时尾行一并省略。
- 不自动引用 chinese-documentation（它声明只在显式 `/` 调用时生效）。中文排版按用户既有习惯。
- 顺序：用户本轮明确要求的格式 > 本技能 > 其他风格类技能（只改槽内措辞，不改框架）。

拿不准时：**清楚赢过整齐**。宁可破格式，也要把话说明白。

持续性：一旦生效，本会话此后每轮沿用，长会话不退化，直到用户说「关掉四段式」「正常回复」或 `/recap off`。
